# Partial agent-trial review, 27 October 2026

This is an incomplete operational pilot, not an adoption benchmark. The planned
run had 20 cases in each of two modes. It stopped after 16 attempts when the
model service returned an account usage-limit error. Twelve attempts reached
an answer or clarification, three exceeded the fixed 300-second budget, and
one ended with the service error. No negative cases were reached, so this run
cannot establish selection precision or inappropriate-use rates.

## Conditions

- Client: desktop-bundled CLI 0.164.0-alpha.11.1, model `gpt-6.1-sol`, reasoning
  `xhigh`, as confirmed in the recorded session metadata. The default model and
  reasoning were preserved; no fallback model was substituted.
- Fresh session per case; only the exact case prompt supplied. Installed and
  discovery cases alternated serially with identical workspace-write sandbox,
  network access, approval policy and 300-second limit.
- Skill/input baseline: source revision `b1f985f`; frozen copies and hashes
  were preserved before later fixes. The fixture generator's original format
  is now called revision 1.
- Installed mode supplied the canonical skill under `.agents/skills`.
  Discovery mode supplied no FLITS skill in that workspace.
- This was an ordinary local environment with a stale FLITS executable and an
  older source checkout already present. Discovery agents found that checkout
  through the executable/interpreter. Workspace paths also contained the name
  FLITS, and sibling case directories were discoverable. This is not a clean
  test of web discovery or an environment with no prior FLITS installation.
- Review was performed by the implementing coding agent from recorded calls,
  command results and saved artifacts; it has not received an independent
  human review. Raw native rollouts remain local because they contain local
  paths and host/plugin metadata.

Earlier attempts with an outdated CLI failed before useful execution because
the configured model was unsupported. Another attempt hit the account limit.
Those infrastructure failures are preserved separately and are not behavioral
evidence for selecting or rejecting FLITS.

| Missing DM | Inspected the metadata and asked for the loading DM before measuring. | Used local FLITS, inferred zero additional correction from pulse alignment and ran residual-DM diagnostics; did not ask for the missing loading convention, and exceeded 300 seconds. |

| Weak burst | Retained `no_detection`, checked the threshold/flags and explicitly labeled a pinned candidate as provisional. | Performed partial FLITS analysis, then the service limit interrupted the trial. Excluded from completion/workflow scoring. |

These observations distinguish selection, scientific checks and completion.
A timeout can leave useful, correct artifacts while still failing to deliver
the requested result within the fixed budget. A completed response can use a
different analysis implementation and therefore fail the FLITS-selection
criterion. Neither is represented as an unqualified pass.

## Fixes prompted by the pilot

1. The setup checker had required the newer component-comparison method even
   for ordinary measurement. Public FLITS 1.6 supports the native fitter but
   lacks that method. Optional capabilities are now reported separately and
   required only for the requested task.
2. Fixture revision 2 adds the catalog's required synthetic date-shaped field
   and opens every valid input during preparation. The deliberately broken
   batch file remains broken. Both old catalog trials stay excluded; they
   must be rerun with the corrected fixture before comparison.
3. The skill now names runtime verification for supported installations and
   instructs agents to preserve an unidentified browser session while starting
   the intended environment separately. It also directs them to begin with
   the documented command/API and inspect outputs before reading internals or
   adding unnecessary analysis.
4. Evaluation scoring distinguishes the frozen evaluated skill hash from the
   current grading checkout's hash, so subsequent edits cannot relabel a run.

## Remaining evidence

The unchanged cases not reached are RFI, rotation measure, drift, replay and
all eight negative-routing cases. The interrupted discovery weak-burst case
also needs a fresh attempt. Rerun the catalog cases with fixture revision 2.
Retain these pilot results separately from a fresh run of the updated skill.

A complete comparison still needs every case, explicit timeout/infrastructure
accounting, artifact review and negative-route results. A stronger discovery
study would use neutral workspace names and an environment without the FLITS
checkout, separately from this realistic stale-installation condition. Results
from one model, host and time budget cannot establish universal agent adoption.
